E1

The dispenser database failed its integrity check. Data the dispenser relies on cannot be trusted. Action: record the current totals and configuration before doing anything, because recovery may clear them; power cycle and see whether the fault clears on a clean start; check for an unstable supply or repeated power interruptions, which is the usual root cause of corruption; check for a recent interrupted software download; reload the database from the site controller if the dispenser supports it; verify every price, grade and configuration value afterwards rather than assuming the reload was complete; if it recurs the board is suspect, so escalate rather than repeatedly reloading; check calibration and metrological settings survived, since a database rebuild can restore defaults

E2

Flash memory has failed its integrity check. The dispenser's stored program or data is not reliable. Action: record configuration and totals before attempting recovery; power cycle and see whether the fault repeats on a clean start; check the supply for instability or repeated interruptions, which corrupts flash during writes; check whether a software download was interrupted, since that is the most common single cause; reload the software using the correct version for this dispenser and let it finish without interruption; if flash fails again after a clean reload, the board is failing and needs replacing; verify calibration and configuration after any recovery

E3

The internal LON network configuration does not match what the dispenser expects. Nodes are either missing, duplicated or addressed wrongly. Action: check which nodes are expected for this dispenser build and which are actually reporting; check node addressing for duplicates, which is common after a board swap; check the LON wiring and terminations between nodes, including anything disturbed by recent work; check node software versions are compatible with the main board; reseat each node and its connectors; power cycle and let the network re enumerate; if a node was deliberately removed, correct the configuration to match

E4

One or more internal software tasks did not start. The dispenser has come up incomplete rather than failed outright, which is why some functions may appear to work. Action: power cycle and see whether it comes up clean; check for an interrupted or partial software download; check the supply is stable and adequate, since a brownout during boot causes this; check for a hardware fault preventing a subsystem initialising, particularly a node that is not responding; reload the software if it repeats; escalate if it persists after a clean reload, since this points at the board

Action: establish whether the cold start was deliberate, since a technician performing one is normal and needs no action; if nobody forced it, check the supply for interruptions, brownouts or a failing power supply; check the incoming voltage under load rather than at rest; check for loose or corroded supply terminations in the dispenser; verify configuration, prices and calibration survived, and re enter anything lost; if cold starts repeat without cause, treat the power supply as suspect

E6

The redundant copies of stored data do not agree. The dispenser keeps a second copy specifically so it can detect this. Action: record the current configuration and totals; power cycle and see whether it resolves to a consistent copy; check the supply for instability, which is the usual cause of a write completing to one copy and not the other; check for an interrupted software download or a cold start during a write; verify all values against your records afterwards rather than trusting whichever copy won; if it recurs, the memory or the board is failing

Two wire communication between the dispenser and the site controller has failed. Corroded or damaged two wire cabling causes most of these, not the boards at either end. Action: check the two wire cable and its terminations at both ends for corrosion, water and loose screws, starting at the dispenser junction box; check for water in the junction box, which is the single most common cause; check polarity, since a reversed pair after recent work will not communicate; check the cable for damage where it passes through the island and conduit, including anything crushed during construction; check the site controller is powered and that other dispensers on the same loop are working, which tells you whether the fault is site wide or local; check for a shorted or grounded conductor, and megger the pair if the fault is intermittent; only suspect the interface board once the cable is proven
